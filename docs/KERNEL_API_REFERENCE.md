## 1. Asynchronous Event Bus Spine (`IEventBus`)

The `IEventBus` is the decoupled messaging spine of the Kernel. It coordinates communication using synchronous or asynchronous event dispatching, providing task isolation and real-time observer dispatch.

### Interface Definition

```typescript
export interface IEventBus {
  /**
   * Dispatches a type-safe event frame out to all matched listeners.
   * Automatically appends a unique event ID and current RFC 3339 timestamp.
   * @param event Frame input parameters excluding autogenerated fields
   */
  publish(event: Omit<KernelEvent, "eventId" | "timestamp">): void;

  /**
   * Subscribes a listener to trigger when a matching event occurs.
   * Wildcard "*" channel matches every dispatched event.
   * @param type Targeted event type or "*" wildcard
   * @param handler Unhandled-safe callback handler
   */
  subscribe(type: KernelEventType | "*", handler: (event: KernelEvent) => void): void;
}
```

### Constraints & Lifecycle Controls
* **No Listener Overloading**: The Event Bus is protected against Node's default max listeners warning by explicitly setting infinite or extremely high listener limits, or managing subscriptions defensively.
* **Subscription Cleanup**: Handlers should be stored in a collection that permits deletion or cleanup via explicit disposal methods.
* **Synchronous Safety**: Subscribers are run within sandboxed `try/catch` wrappers to prevent subscriber errors from cascading and crashing the dispatching thread.

## 2. Transactional Task State Database (`IStateStore`)

The `IStateStore` is a memory-only, transactionally isolated storage database. It maintains the absolute source-of-truth for all tasks and enforces valid state-machine transition rules.

### Interface Definition

```typescript
export interface IStateStore {
  /**
   * Initializes a new task state entry in memory.
   * Sets up default telemetry matrices and empty step queues.
   * @param goal The plain text goal describing target end-state
   * @returns Uniquely generated UUID string identifying the task
   */
  createTask(goal: string): string;

  /**
   * Transactionally updates the parent status of a task.
   * Blocks impossible or invalid state transitions to ensure machine safety.
   * @param taskId Unique identifier for target task
   * @param status Next state in transition matrix
   */
  updateTaskStatus(taskId: string, status: TaskStatus): void;

  /**
   * Partially modifies an individual execution step inside the task queue.
   * @param taskId Unique identifier for parent task
   * @param stepId Unique logical identifier for target step
   * @param updates Object containing modifications
   */
  updateStep(taskId: string, stepId: string, updates: Partial<TaskStep>): void;

  /**
   * Atomically records incremental LLM token usage or tool execution metrics.
   * @param taskId Unique identifier for parent task
   * @param usage Metric values to increment/track
   */
  recordTelemetry(taskId: string, usage: Partial<TaskTelemetry>): void;

  /**
   * Safely fetches a deep-copy of the target task's current state.
   * Returns null if task ID does not exist in registry.
   * @param taskId Unique task reference key
   */
  getTaskState(taskId: string): TaskState | null;

  /**
   * Optionally updates standardized module version metadata for the task.
   */
  updateTaskMetadata?(
    taskId: string,
    metadata: {
      planner_version?: string;
      context_policy_version?: string;
      verification_policy_version?: string;
      reflection_version?: string;
    }
  ): void;

  /**
   * Lists all task records tracked in memory, sorted by creation timestamp descending.
   */
  listTasks(): TaskState[];

  /**
   * Deletes a task from the state store to free memory.
   * @param taskId Unique task reference key
   * @returns true if task was found and deleted, false otherwise
   */
  deleteTask(taskId: string): boolean;
}
```

### State Machine Transition Contract
Transitions are guarded by an strict state matrix. Modifying a task's status outside this matrix throws an immediate runtime exception:

```
[pending] ──► [planning] ──► [running] ──► [verification] ──► [reflection] ──► [completed]
    │             │              │               │                 │
    ▼             ▼              ▼               ▼                 ▼
[failed] ◄──── [failed] ◄──── [failed] ◄───── [failed] ◄─────── [failed]
```

## 3. Tool Capability Registry (`IToolRegistry`)

The `IToolRegistry` controls environment boundaries by matching executable functions with descriptive manifests. It performs runtime schema enforcement on both inputs and outputs.

### Interface Definition

```typescript
export interface IToolRegistry {
  /**
   * Registers a capability with a strict schema manifest.
   * @param manifest JSON schemas and metadata describing constraints
   * @param handler Promised-based function representing the physical tool
   */
  registerTool(manifest: ToolManifest, handler: (args: any) => Promise<any>): void;

  /**
   * Executes a tool by ID after validating its arguments.
   * @param toolId Target tool registration identifier
   * @param args Parameter dictionary
   * @param taskId Associated tracking task
   */
  executeTool(toolId: string, args: Record<string, any>, taskId: string): Promise<any>;

  /**
   * Lists all currently registered tools.
   */
  listTools(): ToolManifest[];

  /**
   * Retrieves a tool manifest by ID.
   * @param toolId Target tool identifier
   */
  getTool(toolId: string): ToolManifest | null;
}
```

### Execution Protections
* **Validation**: Input arguments are matched against the manifest's `inputSchema` using a JSON validator before executing the tool handler.
* **Timeout Gating**: Executions are wrapped in an asynchronous race timer configured to reject with a timeout error if processing exceeds `manifest.timeoutMs`.
* **Telemetry logging**: Automatically updates the task's tool execution counters.

## 4. Policy-Driven Model Router (`IModelRouter`)

The `IModelRouter` serves as the centralized interface for routing requests to Large Language Models (LLMs). It accepts high-level semantic policies and maps them to concrete parameters and providers.

### Interface Definition

```typescript
export interface IModelRouter {
  /**
   * Sends a prompt with execution parameters matching the chosen service policy.
   * @param prompt User or agent request payload
   * @param policy Intended balance of latency and intelligence ("fast", "reasoning", "bulk")
   * @param systemInstruction System instruction constraints
   */
  generate(
    prompt: string, 
    policy: "fast" | "reasoning" | "bulk", 
    systemInstruction?: string
  ): Promise<ModelResponse>;
}
```

### Routing Policy Contracts
1. **`fast`**: Prioritizes latency. Typically routed to high-throughput, low-latency models (e.g., `gemini-2.5-flash` or equivalents).
2. **`reasoning`**: Prioritizes depth of intelligence, chain-of-thought, and structural planning accuracy. Map directly to advanced reasoning systems.
3. **`bulk`**: Prioritizes high context sizes and token budget economics. Used for mass document evaluation.

## 5. 4-Layer Semantic Context Builder (`IContextBuilder`)

The `IContextBuilder` compiles clean, compressed, contextually dense segments from active workspaces to supply appropriate system and file details to LLM requests.

### Interface Definition

```typescript
export interface IContextBuilder {
  /**
   * Generates a context package containing file content, symbol indexes, and dependency maps.
   * @param query High-level goal context
   * @param impactedFiles Explicit list of workspace paths involved
   */
  buildContext(query: string, impactedFiles: string[]): Promise<WorkspaceContext>;
}
```

### Context Isolation Rules
* **Exclusion Policies**: The context builder must filter out large binary assets, third-party compiled modules (`node_modules`), package lockfiles, and environment files (`.env`).
* **Budget Gating**: Compresses content using heuristic strategies (comment stripping, signature summaries, or truncated snippets) to respect strict system token allocations.

## 6. Non-Linear Task Planner (`IPlanner`)

The `IPlanner` translates broad user goals into structured, executable, DAG-compatible sequences of modular operations.

### Interface Definition

```typescript
export interface IPlanner {
  /**
   * Forms a structured collection of executable steps based on user goals and workspace states.
   * @param taskId Unique tracking task ID
   * @param goal Original user request
   * @param context Active context compilation
   */
  createPlan(taskId: string, goal: string, context: WorkspaceContext): Promise<TaskStep[]>;
}
```

### Integrity Controls
* **Predefined Ordering**: Output steps must describe discrete and testable steps (e.g., plan, edit, compile, verify).
* **Metadata Attachment**: The planner attaches `planner_version` to state transitions to facilitate performance telemetry analyses.

## 7. Verification Gateway (`IVerificationEngine`)

The `IVerificationEngine` is the strict Definition of Done (DoD) gatekeeper. It runs automated, structured checks against workspace files before letting tasks transition to completed statuses.

### Interface Definition

```typescript
export interface IVerificationEngine {
  /**
   * Executes verification rules against specified file paths.
   * @param taskId Target tracking task ID
   * @param filePaths List of files to verify
   */
  verify(taskId: string, filePaths: string[]): Promise<{
    success: boolean;
    logs: string[];
    errors: string[];
    verification_policy_version?: string;
  }>;
}
```

### Safety Scorecards
The gatekeeper runs multiple strict, isolated checkers:
1. **`BannedSyntaxRule`**: Block illegal constructs (such as `const enum` declarations).
2. **`CompilationRule`**: Validates the code compiles cleanly via runtime commands.
3. **`SecurityLeaksRule`**: Discovers hardcoded secrets or API key fragments before persisting modifications.

## 9. Core Orchestration Loop (`IAgentRuntime`)

The `IAgentRuntime` is the main driver. It controls execution steps sequentially, managing transitions, recording telemetry, and executing recovery maneuvers.

### Interface Definition

```typescript
export interface IAgentRuntime {
  /**
   * Runs the complete lifecycle loop for an initialized task from planning to reflection.
   * @param taskId Target tracking task ID
   * @returns true if task successfully compiles and passes verification, false otherwise.
   */
  executeTask(taskId: string): Promise<boolean>;
}
```

### Operational Loop Lifecycle

```
[Start Task]
     │
     ▼
[Plan Phase] ──► Event: PlanningStarted ────► Event: PlanningCompleted
     │
     ▼
[Step Loop]  ──► Event: ToolExecuted
     │
     ▼
[Verify]     ──► Event: VerificationPassed ─┬─► Event: VerificationFailed
     │                                      │
     ▼                                      ▼
[Reflection] ──► Event: TaskCompleted       [Rollback / Fail] ──► Event: RollbackTriggered
```
